它到底是什么

一句话说清定位,省得你在文档里翻半天。

是什么

一个用 Go 写的、从词法分析到字节码虚拟机全部自己实现的 JavaScript 运行时。不是 V8 的绑定,也不是把 JS 翻译成 Go。

能做什么

跑 ES6+ 脚本、写 CLI 工具、写带窗口的桌面程序、把脚本打包成单个可执行文件发给别人,以及拿它学运行时原理。

不做什么

不追求替代生产环境的 Node 生态:没有 npm 兼容、没有 require、没有 JIT,也不实现 DOM。当作一门独立的小语言 + 自带 UI 框架来用。

为什么是 Gox

不是又一层封装,而是从 Token 到虚拟机的每一层都自己写。

快速开始

三种进入方式,按你的目标挑一个。

方式一:脚手架建工程推荐
npm i -g @goxjs/goxjs
gox create my-app
cd my-app
npm install
npm start
方式二:npm 装运行时无需 Go 环境
npm i -g @goxjs/goxjs   # 内置 5 平台预编译二进制
gox                 # 进入 REPL
gox app.js          # 运行脚本
npx goxjs app.js    # 不安装直接跑
方式三:从源码构建Go 1.26+
git clone https://github.com/14752222/Gox.git
cd Gox
go build            # Windows 下生成 Gox.exe
./Gox app.js

左边是语言能力,右边是一个 16 行的响应式 GUI 桌面应用 —— 点击按钮计数,只重绘受影响区域。

语言与宿主能力
// ES6+ 子集(let/const,不支持 var)
let [a, b] = [1, 2];
console.log(`${a + b}`);            // 3

// class / async / await
class Point {
  constructor(x, y) { this.x = x; this.y = y }
  norm() { return Math.hypot(this.x, this.y) }
}

async function main() {
  let v = await delay(10, "timer done");
  console.log(v);
}

// fs / http / fetch / process 全局可用
let cfg = fs.readFileSync("app.json", "utf-8");
let res = await fetch("https://example.com/api");
GUI 桌面应用(counter.js)
import { createSignal } from "gx/solid";
import { h, render } from "gx/gfx";

const [count, setCount] = createSignal(0);

render(
  <window title="Counter" width={400} height={300}>
    <column gap={8} padding={16}>
      <text font={20}>{() => `count: ${count()}`}</text>
      <button onClick={() => setCount(c => c + 1)}>加一</button>
    </column>
  </window>
);

// gox counter.js      → 弹出 400x300 窗口
// go run ./packager counter.js --gui -o counter.exe
//   → 打包成独立 GUI 程序

架构

一条清晰的编译管线,每一层都可以单独阅读和测试。

.js 源码UTF-8 文本
→
lexer词法分析 → Token 流
→
parser语法分析 → AST
→
compiler符号表 + 字节码生成
→
vm栈式帧执行 + 事件循环

无 GC 的显式内存管理

对象生命周期由运行时显式控制,循环引用有专门处理,不依赖 Go 的垃圾回收器托管 JS 堆。

单线程 VM + 跨 goroutine 调度

http.createServer 等网络回调跨 goroutine 捕获后调度回 VM 单线程执行,无需锁。
